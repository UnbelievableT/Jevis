# 验收与评测

## 本次框架验收

- 本地 API 能创建和查询演示任务，所有真实提供方显示未接入。
- 工作单元不能跨越未完成依赖；循环和缺失依赖被拒绝。
- 暂停后不可推进；旧修订和非法转移被拒绝。
- 任务快照、事件和幂等回执同事务写入。
- 数据库关闭再打开仍能恢复任务，重放同命令不重复事件。
- 身份、Origin、输入、大小和副作用边界有明确行为。
- CAS 能取回证据并检出摘要损坏。
- 桌面/移动/官网构建，UI 主流程和窄屏布局实际检查。
- Tauri 原生壳至少完成本机 cargo check。
- 上游版本及许可证路径可追溯。

精确检查结果见 [status](status.md)，运行证据截图在 screenshots/。这是框架检查，不是生产完整验收。

## 完整功能验收

真实 Codex/Claude/Pi 适配、模型/子 Agent 约束、规格修订、上下文取回、并行调度、冲突集成、真实测试与审查、共享池预算、停机/重启/供给失效/未知副作用恢复、平台沙箱、设备配对、撤销、安装升级均需要独立集成验收。

故障注入覆盖：写入前后、预算预留后、调用中、产物落盘后、集成中、审批变更、失去租约、磁盘不足和网络断开。演示测试不能替代这些场景。

## 收益评测

同一仓库起点、权限和独立验收，比较 A 强模型、B 普通模型、C 混合无 Jev、D 完整混合含 Jev。再关闭上下文筛选、升级或经验分别消融。

报告合格率、含失败成本的每个合格交付费用、强模型资源、总延迟、人工修复、错误放行、误拒及升级。订阅额度与 token/美元不能混为一个数。中文与英文分开看，固定模型、问题包和策略版本。

原 v3 提出的“合格率下降不超过 3 个百分点、强模型资源下降至少 30%”是待评审目标，不是实测结果。达到目标需要预注册任务集和置信区间；样本规模由方差与检测目标决定。

冻结的验收与 held-out 数据不用于每轮调参。Jevis 的真正有效性以对照结果为准，不能以界面完整度或某个 Cookbook 数字推断。
