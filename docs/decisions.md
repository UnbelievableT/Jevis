# 架构决策记录

| 编号    | 决策                              | 理由及影响                                       |
| ------- | --------------------------------- | ------------------------------------------------ |
| ADR-001 | 独立 Jevis 仓库，6 应用/21 内部包 | 避免混入业务仓库，按契约并行实现                 |
| ADR-002 | Tauri 2 + React + TypeScript      | 共用桌面/手机 UI；不完整 Fork 不兼容的多个客户端 |
| ADR-003 | Node.js 24 独立 daemon            | UI 生命周期与任务分离；当前原生壳手动启动服务    |
| ADR-004 | SQLite WAL + CAS                  | 本机事务状态和大产物分别管理；不放网络共享盘     |
| ADR-005 | HTTP v1 + SSE + 共用 Client       | CLI/MCP/UI 消费同一状态，避免多个调度内核        |
| ADR-006 | Agent 与 inference 适配并存       | 官方宿主能力与可控制的 Pi 循环各有所用           |
| ADR-007 | Jev 只返回判断信号                | 权限、预算、状态、发布由确定性代码控制           |
| ADR-008 | demo 明确隔离                     | 无真实调用时不伪造能力、费用或质量证据           |
| ADR-009 | deps 是上游源码库，不是构建输入   | 可研究/移植，保留 SHA/许可证，避免互相嵌套框架   |
| ADR-010 | 不默认开放远程端口                | 手机远程必须有配对、TLS 与设备凭据               |
| ADR-011 | 先保留内部包 private              | 自有代码公开授权方式待所有者决定，第三方授权独立 |
| ADR-012 | 单一完整范围，不列优先级          | 模块依赖用于工程组织，完成状态不改变产品范围     |
