# Jev、预算与租约实现记录

日期：2026-09-19。本文描述实际代码；完整产品范围仍见 technical-spec-v3.md。

## Jev

`packages/judge/src/jev.ts` 使用官方 `@typesafe-ai/sdk@0.6.0`。构造时必须提供 API key、明确的模型 ID 与云端数据许可；没有许可时在网络请求前拒绝。固定官方 HTTPS endpoint，关闭 SDK 日志，防止环境变量意外把项目证据发送到其他服务。

问题 ID 唯一且受长度约束；choice 至少两个不重复选项；score 使用从零连续的等级及每级文字描述，保留小数期望分；noul 仅保留概率，不伪造 confidence。响应会校验题型、选项、概率分布、范围及 token usage。记录请求模型和实际返回模型，便于追溯别名变化。

每次请求最多 64 个问题、序列化 UTF-8 数据最多 30 KB。这是保守的数据量限制，**不是精确 token 计算，也不是供应商完整上下文窗口的实现**。总超时默认 15 秒，支持调用方取消。自动重试关闭，避免在不能判断是否计费时重复提交；完整调度器未来用持久化操作记录决定是否重试。

配置 shell 环境变量 `TYPESAFE_API_KEY` 和 `JEVIS_JEV_MODEL` 后运行：

```bash
pnpm cli judge-check --allow-cloud
```

该命令只发送内置英文合成案例，不读取项目文件。`--allow-cloud` 是本次命令的显式传输许可；不会保存为全局授权。不自动读取 `.env`。本轮没有真实 API key 调用结果；测试使用传输层固定响应，不能证明模型效果或实际成本。

## 持久化预算

`DurableBudgetLedger` 使用 SQLite WAL 和 `BEGIN IMMEDIATE`；多个连接按同一共享池预留，持久化后进程重启仍保留。金额为整数 micro-USD（1 USD = 1,000,000），避免浮点账目误差。

状态：reserved → dispatched → settled；dispatched 可进入 unknown；只有未派发的 reserved 可以 released。unknown 继续占用预留，必须收到实际费用才能结算。费用超过预留或池上限时如实记录 overspent，不把费用截断。预留 ID 和结算具有幂等/冲突校验。

账本目前是独立模块；**尚未与任务状态、调度命令、模型派发加入同一个事务**。因此现有演示任务仍使用演示逻辑，不能把此模块的单元测试当作生产费用闭环证明。订阅额度不按美元虚构折算，后续另建供给额度资源池。

## 执行租约

同一资源未到期前只能由一个 holder 持有。重新获取时 fence 单调递增，续约要求资源、holder、fence 和未过期时间全部匹配；旧进程不能续约新持有者的租约。

目前仅实现租约存储与续约拒绝，尚未将 fence 检查加入 Runner 产物提交和任务写入事务；不是完整副作用隔离。依赖本机系统时钟，不是分布式时钟协议。后续需要把执行收据、检查点和未知副作用对账接入。

## 验证

测试覆盖两个独立连接共享预算、重新打开数据库、幂等冲突、未知费用保留、超额实账、过期 holder 拒绝续约，以及 Jev 的外发许可、超量输入、错误概率标签、分数/概率语义和无自动重试。所有夹具都使用合成数据。
